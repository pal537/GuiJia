重点端口洪峰防护 分布式爆破

防的是代理池分布式爆破：攻击者用成百上千个代理 IP、每个 IP 只试一两次，上面那种「单个 IP 失败 N 次」的阈值永远抓不到。开启后，同一个重点端口若在短时间内涌入大量不同来源 IP，将判定为洪峰，立即临时关闭该端口并通过 TG 升级报警。
启用洪峰防护
只对重点（星标）端口生效
触发条件
分钟内，同一重点端口出现个不同公网 IP 的新连接
触发动作
临时关闭该端口分钟：期间公网新连接全部拒绝，内网不受影响；到期自动恢复，也可在「端口」页立即恢复
注意：下载类端口（qBittorrent、Transmission 等 BT 下载）千万不要设为重点端口——BT 对端成百上千是正常流量，会误触发关端口。重点端口只适合 SSH、面板、管理后台这类来源 IP 很少的服务。

扫描识别 被动观察

只看、不探：从本机连接与内核连接表里被动观察某 IP 在短时间内触达的不同 TCP 端口数，达阈值即判定为扫描。闭口试探（对方敲没开的端口）也能看见，因为它在内核连接表里留痕。采样间隔 1 秒；亚秒级全端口快扫理论上可能漏报。内网与信任名单豁免。

蜜罐 默认关

⚠️ 谨慎开启
1. 先改默认端口（重中之重）：SSH 和 webui 必须已经改离默认端口（建议 50000 以上高位），改完同步改路由器转发和客户端收藏。没改之前，默认端口当蜜罐根本不成立——真服务就占在上面，校验会直接拒绝；而且真服务挂在默认端口上，等于天天站在批量扫描的枪口下。
2. 必须在软路由上把蜜罐端口转发到 NAS 本机，否则 0 命中不是坏了，是没转发；转发目标必须是 NAS 本机 IP。蜜罐别走雷池（雷池只反代真服务，走它来源 IP 会被挡一层）。
3. 蜜罐端口绝不能是真服务端口（分层校验会拦截：格式 → 自身 → 系统已知 → 实时监听 → 历史流量 → 终局 bind，任一层拒绝都会说清被谁占了）。
4. 蜜罐不提供任何真实服务，也不仿真登录页面；对方发来的数据只记录、不执行。
5. 批量扫描量很大，蜜罐一开报警量会明显上涨，这是正常的。
6. 建议先只开 1～2 个（比如 22、3389）试效果，不要一次全开。改端口防的是批量扫描，防不住定向攻击；真正的防护还是密钥登录、强密码。
